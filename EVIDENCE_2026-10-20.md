# Implication Space — Evidence Record

Compiled 2026-10-20. Every claim below names its method and its file.
Tests were run in Python on Mia's VM; rerun any of them to reproduce.

## What Implication Space is (Christopher's definition)

Only the real bits are stored; everything else is implied by the
rules. A primitive multiplier multiplies **the bits used to
calculate** — not the numbers: each real bit becomes an implication
space (fan-out rule: bit i → 2i, 2i+1; then blocks of 16; then blocks
of 256). The full compute is partitioned into quadrants of four bits,
each bit seeding its own space. The layer count is a **VAR** that
keeps the same progression (each layer doubles); the historical
widths 4, 8, 128, 32,768 are checkpoints on that progression
(32,768 = 4 bits at L=13), not fixed stages.

Implication Space does not compute. It supplies bits; ordinary
computation runs on them.

## Positive evidence

**1. The multiplication is exact.**
`bit_multiplier_v0.py`, `quadrant_multiplier_v0.py`,
`layered_space_v0.py` — 29 automated checks, all passing
(2026-10-20): widths 4→8→128→32,768; on-demand (provenance) values
equal the materialized space at every position checked; each real
bit has exactly 8,192 descendants at the canon setting; one quadrant
reproduces the primitive multiplier exactly at every stage;
re-setting the layers VAR re-implies the space with the real bits
unchanged.

**2. State does not grow with the space.**
`benchmark_bitsupply_v0.py` (log: `benchmark_bitsupply_2026-10-20.log`),
64 real bits:

| L | space width (bits) | normal state | implied state |
|---|---|---|---|
| 8 | 16,384 | 2,048 B | 72 bits |
| 13 | 524,288 | 65,536 B | 72 bits |
| 18 | 16,777,216 | 2,097,152 B | 72 bits |
| 23 | 536,870,912 | 67,108,864 B | 72 bits |

**3. Having the space costs nothing and does not scale.**
Instantiation: implied 0.003 ms at every L tested. Normal
materialization (fastest honest build, byte-level repetition):
0.02 ms → 0.05 ms → 2.18 ms → 110.67 ms across the same L range,
growing with width.

**4. Ordinary computation consumes implied bits at full speed.**
XOR-fold over 20,000 random positions (an ordinary computation
reading its working bits), reads verified identical on both sides
(2,000 sampled per setting): normal 3.2–6.9 ms vs implied 4.1–4.2 ms
— parity within noise at every L. The computation is not taxed for
using implied bits.

**5. Spaces that cannot materially exist still supply correct bits.**
At L=40 the space is 70,368,744,177,664 bits (8.8 TB as material);
at L=60 it is 73,786,976,294,838,206,464 bits (~9.2 exabytes). No
machine can allocate either. Implied answered 10,000 reads in
2.1 ms (L=40) and 2.5 ms (L=60), from 64 stored bits.

## Negative evidence (what was proven NOT to hold)

**6. No new information.** Audit (2026-10-18, accepted by
Christopher): the structure is formally a [32768, 4, 8192]
repetition code. The implied bits carry no information beyond the
real bits; the redundancy buys nothing on a noisy channel in the
Shannon sense. The space is a supply mechanism, not an information
source.

**7. Burst corruption defeats the redundancy.**
`explore_burst_addressing.py` (2026-10-19): majority recovery
tolerates ~40–45% random (i.i.d.) bit flips, but corruption in
bursts is far more damaging per flipped bit — at 20% total
corruption: 1 burst → 19.3% failure, 4 bursts → 90.5%,
16 bursts → 100%.

**8. It cannot serve as an address space.** (2026-10-19, closed.)
Fan-derived 64-bit keys for ReflexStore addressing collide
catastrophically (2–4 distinct keys per 2,000 chunks, all
selector/seed combinations): positional implied outputs carry only
~real-bits of entropy.

## Scope note

The gates-fan races and benchmark (`gates_fan_v0.py`,
`race_multiplier_v0.py`, `race_quadrants_v0.py`,
`benchmark_layers_var.py`) measure a **different construction** —
on-demand gate computation (the Pie Compute line) — and are not
evidence about Implication Space. They were briefly mislabeled as
such on 2026-10-20 and corrected the same day at Christopher's
direction: "implication space is only meant to multiply the amount
of bits used, we would never actually use the fan out computation."
Christopher's verdict "I would call that a win for implication
space" (2026-10-20) was given during the fan-benchmark discussion;
the corrected evidence above stands on its own measurements.
